# Threads Studio 安全運用ルール（2026-09-06 制定）

アカウント停止（2026-09-06 だいご接骨院）を二度と起こさないための、システム・お客様・運営の三者のルール。
変更するときはこの文書を先に直し、コードと説明書を合わせる。

## 1. システムが自動で守ること（コードで強制）

| ルール | 実装 |

## 2. お客様にお願いすること（説明書・LINEヘルプ・連携直後の案内に記載）

1. 連携から2週間は、ご自身の手動投稿も1日1〜2件まで。フォロー・いいねの連打をしない
2. 価格（初回◯◯円）や結果の断定（治る・歩けるようになった・ぐっすり眠れた）は書かない。入口は固定投稿とプロフィールのリンク
3. プロフィール（名前・自己紹介・アイコン・リンク）を先に整える。空のまま投稿を増やさない
4. 本人確認（ロボット判定・電話番号・顔写真）が出たら正直に完了する。停止なら異議申立は1回、結果まで投稿・フォロー・いいねを控える
5. 復帰後2週間は1日1〜2件。復帰したら公式LINEで知らせる
6. Threadsアプリを日常的に開く（見るだけでよい）。APIからしか活動が無いアカウントにしない

## 3. 運営が毎朝確認すること（threads-studio-daily-check）

- `account_health` が動いたか、自動停止・投稿消失の通知が出ていないか
- 慣らし運転中（連携10日未満）・補填中（11〜30日目）のアカウント一覧と、当日の上限で見送った件数
- healthClaimGuard の発動が多いアカウント（登録内容に結果表現・価格が多い＝はじめの設定の見直しをLINEで案内）
- 自動停止されたアカウントは、お客様の復帰連絡があるまで再開しない。再開時は慣らし運転（1件/日）から

## 4. 停止が起きたときの手順（運営）

1. 事実を集める：連携日・フォロワー・直近7日の投稿（自動＋手動）・本文の表現・自己コメントの有無・API応答
2. そのアカウントの自動投稿を止める（自動停止していなければ手で）。Meta AI呼びかけも一時OFF
3. お客様へ：原因を「密度と表現」で説明し、本人確認と異議申立の手順を案内（過去の制限歴などの推測は前面に出さない）
4. 他のアカウントに同じ型（新規・高密度・結果表現）が無いかを点検し、あればその日のうちに本数を落とす
5. 記録：memory `project_threads_account_suspension` に追記

## 5. 変更するときの決まり

- しきい値（5日/10日・1件/2件・補填＋1件・30日で契約どおり）を変えるときは、この文書 → shared/accountRamp.ts → 説明書 の順で同時に直す
- 新しい業種を扱うときは healthClaimGuard の業種判定と言い換え表を先に足す
- 本番反映は夜間整備でまとめて行い、日中は反映しない（例外は実害が出続けているときだけ）

## 追記 2026-09-10：作り直しで枠を捨てない／直近の投稿の使い回しを止める

- **この店らしさ（`shared/identityGuard.ts`）は、落ちてもすぐには作り直さない。** 口語リライト（`naturalizeContent`）が「50〜100文字に収める・情報は削ってよい」の指示どおり店名・地名を先に削ることが多く、下書きには入っているのにここで落ちて枠ごと捨てられていた（2026-09-09：この理由で複数の枠が3回とも落ち、その日の投稿がゼロになった方が出た）。リライト前の文が同じ検査（この店らしさ・登録口調・決まり文句）を通るなら、**作り直さずリライト前の文に戻す**。両方だめなときだけ作り直す。ガードの基準は緩めていない。
- リライトには、下書きに実在する「この店を指す言葉」だけを**消してはいけない言葉**として渡す（`naturalizeContent` の `keepWords`）。
- **直近の投稿の使い回しを止める（`shared/jpQualityGuard.ts` の `findRepeatedPhrase`）。** 生成時に直近8本の本文をプロンプトへ渡し、14文字以上つながって一致する言い回しがあれば作り直す。ただし**最後（3回目）の作り直しでは止めない**（程度の問題で投稿ゼロにしない。記録だけ残す）。2026-09-09、切り口は毎回違うのに書き出しの決め台詞だけが同じ投稿が5本続き、お客様が5本とも「✕ 違う」を付けて4本を見送られたため。
- 慣らし運転の日数は、お客様に見せる文ではすべて `rampDayLabel()`（連携した日が1日目）を通す。生成側「8日目」・公開側「7日目」とずれていた。
- LINEのプッシュが月間通数切れ（429 + monthly limit）で届かなかったときは、**同じ内容をメールでお届けし**、運営にも1日1回知らせる（`server/lineNotify.ts`）。2026-09-09に22件が黙って消えた再発防止。朝の点検（`scripts/ops/daily-check.mjs`）に残量を表示し、残り1割で警告する。

## 追記 2026-09-11：指示と検査の矛盾を作らない（絵文字・締めの言い方）

品質ガードは緩めていない。**こちらの指示どうしが矛盾していたのを直した**という位置づけ。

- **絵文字を消してよいのは「落ち着いた口調だけを登録し、お手本も絵文字を使っていない方」だけ**（`shared/styleTraits.ts` の `emojiAllowed`）。
  生成の最終指示は「絵文字を1〜3個、毎回必ず入れる」なのに、口語リライト（`naturalizeContent`）は口調に「敬語・丁寧」が入っていると全員から一律に消していた。
  そのあとのAI採点（`server/naturalnessReview.ts`）はお手本（絵文字あり）と比べて「絵文字が無い」と落とすので、作り直しても同じ理由で落ち続ける。
  9/10は岩根様（㈱津の国や本店）の3枠すべてが3回とも 2/5 で落ち、その日の投稿がゼロになった。
  「丁寧な敬語＋少しフレンドリー」は契約中7名のうち4名が登録している一番多い口調で、全員がこの矛盾を踏んでいた。
- **です・ます を保ったあたたかい締め（「〜していますよ😊」）は、フレンドリーも登録している方には認める**（`findWarmClosers`）。
  「〜だね」「〜だよ」「〜かな」「〜でしょ」は、です・ます が崩れるので敬語登録では従来どおり不可（`findCasualClosers`）。
  比嘉先生（口調「敬語で落ち着いた口調、沖縄出身でゆったりとした口調」）はフレンドリーの登録が無いので、これまでどおり不合格のまま。
- **疑問詞のある短い問いかけは通す**（「もし着物で海外へ行くなら、どこへ？」）。名詞で切って何を聞かれているか分からない形（「〜など、心当たり？」）は従来どおり不可。
- **お手本の癖は数えて指示に書く**（`shared/styleTraits.ts`）。絵文字の個数・ハッシュタグ・店主自身の体験の有無を実測して生成プロンプトに渡す。「お手本を読み取って再現して」だけでは毎回落ちていた。
- 取りこぼしの修正：絵文字パターンに `?` を付けた形が丸ごと括られておらず、**絵文字の無い「〜だね」「〜かな」を1件も拾えていなかった**。
- ここを変えたときは、必ず `server/voiceGuard.test.ts`（比嘉先生の実例と岩根様の実例の両方が入っている）を通す。

## 追記 2026-09-12：「大量のアクション」判定を避ける（しっとる公式の投稿削除を受けて）

- 削除理由は「他の人の迷惑になる可能性のあるアクションを大量に実行」＝文面ではなく機械的な動きの量。返信権限のある4アカウントは投稿ごとに「リンク付き自己コメント」＋「定型文の自己返信（追い投稿）」を付けており、1日で投稿4＋自己返信4、同じ文の返信が同日に2回あった。
- 追い投稿（自己返信）は**既定OFF・全員OFF**（`users.autoFollowUpEnabled`）。再開するなら定型文をやめ、1日1件・本人が承認したものだけ。
- リンク付きの計測コメントは**1アカウント1日1回**（その日の1件目だけ）。固定投稿のコメントは従来どおり。
- 投稿が1件でもThreads側で消されたら**7日間の冷却期間**（`threadsAccounts.cooldownUntil`）：1日1件・補填なし・自己返信/リンクコメントなし・Meta AI呼びかけボタンなし。7:40の報告に理由を出す。しっとる公式は 9/19 まで。


## 追記 2026-09-13：1日の本数を守る7つの決まり（三上様決定「これら全てを今夜アップデート」）

事実：9/12 に Moveact 10件・しっとる公式 8件・滝本様 8件・岩根様 8件が公開された（全体65件／平常38件前後）。
原因は「追い投稿が契約本数の外で出ていた」「歴の長いアカウントに1日上限が無かった」「前日の確認カードが翌日に残り、当日分と合わせて9枚が同じ日に届いた」の3つ。直後にしっとる公式と @miraiseitai.diet の投稿が削除された。

1. **1日の公開上限は全アカウント一律。** 上限＝契約本数＋補填分（最大＋2）。承認済みでも超えた分は翌日の枠へ送る（見送りにしない）。自動投稿だけを数え、手動投稿は数えない（慣らし運転・冷却中だけ手動込みで見る）。契約本数の外で出るもの（追い投稿など）は作らない。
2. **日をまたいだ承認待ちは、設定に関係なく見送り。** 翌朝また新しい投稿を届ける。溜めない。固定投稿の下書きは対象外。
3. **仕組みの変更のお知らせは案内OFFの方にも届ける。** 案内OFFで止めるのは毎朝の自動案内（次にやること・自動にしませんか）だけ。LINE未連携の方にはメール。
4. **「今日から」のお知らせは、Coolify のデプロイ記録で反映を確かめてから送る。** push しただけでは反映されない日がある（9/12 は日中のコミットが翌 01:52 まで動いていなかった）。
5. **投稿が消されたときは、検知した当日に運営から定型文で連絡する（承諾済みの型）。** 冷却に入った日は、その日の残りの予定も1件に絞る。
6. **補填は「減った分＋消えた分」を、冷却明けから1日＋1件ずつ。** 30日単位で契約本数を必ず満たす。自社アカウント（しっとる公式・Moveact）は補填しない。
   連携30日以内でも同じ（2026-09-17 に是正）。以前は消えた分の補填が「連携30日を過ぎたアカウント」だけに掛かっており、
   ライトプラン（契約1日1件）の方は30日目まで1件も戻らなかった。慣らし運転中・冷却中は増やさないのは変えていない。
7. **承認の記録（時刻・押したボタン・自動公開か）を必ず残す。** 「本当に承認したか」を手直しの時刻から推定しない。

運営の決まり：**「反映済み」「停止済み」「正常」は、デプロイ記録と実データで確かめてから書く。**
冷却中に止めたときの通知は「投稿が消されたため◯/◯まで1日1件」と伝える（「連携1日目の慣らし運転」と出ていた文言は誤り・9/13）。

## 追記 2026-09-16：健康表現は「最初から書かせない」（設定に書かれていても渡さない）
