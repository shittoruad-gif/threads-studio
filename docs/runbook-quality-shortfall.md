# 手順書：採点（品質チェック）で落ちて、その日の投稿が減ったとき

2026-09-11 三上様指示「採点基準に引っかかった場合は、新たにきちんと投稿できる形で補充するのをマニュアル化」。

## 何が起きるか
- 朝6時の生成は、下書きを口調・らしさ・AI採点・NGワード・健康表現・数字・使い回しの順に検査し、落ちたら最大3回作り直す。
- 3回とも落ちた枠は作られない。その数はアカウントの `shortfallDate / shortfallCount` に記録され、翌朝の生成で自動補填（＋1〜2件）される。
- ただし「翌朝」では、その日の契約本数に届かない。**その日のうちに補充する**のがこの手順。

## 毎朝の手順（朝の点検 08:02 で必ず実行）
1. 不足を出す
   ```
   npx tsx scripts/ops/fill-shortfall.mts --dry
   ```
   「今朝の生成で消えた枠」が出たアカウントが対象。出なければ終わり。
2. 補充する（承認カードはいつもどおりお客様に届く。運営の承認は不要）
   ```
   npx tsx scripts/ops/fill-shortfall.mts --fill
   ```
   - 手元の最新コード（main）で実行する。本番の版と検査の条件が違うことがあるので、直した検査は先に手元へ入れる。
   - 1枠あたり1〜2分。10枠を超えるときは裏で動かし、結果のログを残す。
3. 結果を確かめる
   - 「補充後の今日の本数」が契約本数（慣らし中はその本数、補填中は＋1）に届いているか。
   - まだ足りないアカウントは、同じコマンドをそのユーザーだけで1回だけ再実行（`--fill <userId>`）。2回やっても足りなければ、理由（採点の内訳）を控えて三上様へ報告する。無理に増やさない。
4. 報告に書く
   - 対象アカウント・不足数・補充後の本数・落ちた理由の内訳（採点2/5・3/5・同じ言い回し・健康表現・口調）。

## 補充で作った投稿の質を落とさないために
- 補充も同じ検査を通る。緩めるのは「最後の作り直し」だけ（AI採点3/5は通す・2/5以下は落とす。同じ言い回しは14文字以上の一致だけ落とす）。
- 店名・地名・実績の数字は「使い回し」に数えない（毎回入ってよい言葉）。
- ご本人がThreadsで投稿した直近の内容とも重ねない。
- 見送りが続くお客様は、文体のお手本（styleSamples）が古い・少ないことが多い。`fillStyleSamplesForAccount(accountId, {force:true})` で本人の直近投稿から入れ直してから補充する（2026-09-11 香取様で実施）。

## お客様への連絡
- 補充でその日の本数に届けば、連絡は不要（7:40の朝のまとめと承認カードで分かる）。
- 届かなかった日は、翌朝の自動補填の対象になる。契約本数より少ない日が2日続いたら、個別にお詫びと補填の日程を送る（`shared/personalNotices.ts` に入れて7:40のまとめの直後に届ける。文面の型は `scripts/ops/announcements/2026-09-11_shortfall_apology/`）。

## やらないこと
- 採点の基準（NATURALNESS_MIN_SCORE=4）を日中に下げない。基準の変更は夜間整備で、テストと一緒に。
- 日中の本番デプロイはしない。補充は手元のコードから本番DBに向けて実行する。
- 落ちた枠を「同じ言い回し」のまま無理に出さない（同じ内容が続くと本人が離れる。9/10 香取様）。
