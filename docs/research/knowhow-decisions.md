# Threads運用ノウハウ投稿の採否記録

Threads上で流通する「集客ノウハウ投稿」を評価し、生成エンジンへ採用/不採用を
判断した記録。判断基準は (1)自社実測データと矛盾しないか (2)事実ベース原則
（検証不能な盛り・煽りの禁止）に反しないか (3)法規（景表法・薬機法）リスク
(4)**誰からの反応か**——同業・仲間内の共感/情によるいいねは採用根拠にしない。
見込み客に届き、来店・注文・問い合わせ・プロフィール遷移につながる根拠がある型だけを採用する
（2026-08-28 三上さん指示。同・業種インサイトにも適用済み）。

## 2026-08-28（三上さん提供のスクリーンショット4系統）

### 出典1: 治療院向け8ステップ構成（感嘆→悩み名指し→権威→独自メニュー+変化→社会的証明→オファー→諦めた層回収→限定CTA）

| 要素 | 判断 | 理由・実装先 |
|---|---|---|
| 悩みで名指し | 採用済み | 既存ルール（場面まで具体化）と一致 |
| 権威づけ（資格・人数） | 条件付き採用 | 入力済みの事実のみ。→ 新切り口 reservation_funnel(2) |
| 独自メニュー+変化 | 採用 | 施術名でなく変化を書く既存ルールと一致。→ 同(3) |
| 社会的証明（遠方から来店） | 条件付き採用 | 入力に実在する場合のみ使用可（勝手に作らない） |
| オファー（元値→初回値） | 条件付き採用 | 入力済み価格のみ。→ 同(4) |
| 諦めた層の回収 | 条件付き採用 | 他店・他手法の批判にならない受け止め表現のみ |
| **限定+CTA（予約枠に限りあり・お早めに）** | **不採用** | 検証不能な希少性の煽り。factGuardの禁止事項・景表法リスク・三上さん方針（煽らない）に三重で抵触 |
| 感嘆で始める（体験者の第一声） | 採用 | customer_voice切り口と一致。実在の声のみ |

→ 実装: `shared/postAngles.ts` の `reservation_funnel`（煽り抜き版）

## 2026-09-03（週次リサーチ・検索語「サロン 集客」20本 /「スレッズ 伸ばし方」18本）

この週に拾えたノウハウ投稿は**採用ゼロ**。理由は観客フィルタで全滅したため。
（コーパス: `docs/research/2026-09-03/knowhow_*.txt`）

| ノウハウの主張 | 判断 | 理由 |
|---|---|---|
| 伸びているアカウントにいいね・フォロー・コメントして「アクティブ層」に入る | **不採用** | 反応の出どころが同業・相互フォロー勢。表示回数は増えても見込み客に届く根拠がない。自社は自動投稿の運用で手動の相互行為は前提にしない |
| 「アカウントパワーのお裾分け」への参加 | **不採用** | 同上。この検索語で最上位（1,241いいね）だが、コメント欄は同業のみ |
| 「フォロバ100%」「インサイト祭り」への参加 | **不採用** | 同上（最上位7,016いいね）。フォロワー数は増えるが購買層でない |
| 1行目のフックが最重要 | **採用済み** | 既存ルール（1行目に客の心の声・場面の具体）と一致。追加実装なし |
| 投稿時間帯が決まっている | **採用済み** | 自社実測の15時／21時で既に配線済み |
| 土日は投稿時間を変えると伸びる | **要検証** | 自社データで曜日×時刻の検証をしていない。実装しない |
| アルゴリズムが変わり従来のフックが効かなくなった | **要検証** | 出典は個人の3週間観察のみ。自社の切り口別実測に変化の兆候なし |

**この週の別の収穫**: 「サロン 集客」で拾えるのは見込み客ではなく**サロンオーナー自身の相談・弱音**だった
（ホットペッパー依存の迷い／広告制限がかかった／予約が入らない月の焦り／SNSをやっても反応ゼロ）。
これは Threads Studio 自身の見込み客の悩みの型であり、しっとる側の発信（deep_worry）の素材になる。
ただし実在投稿の文言はコピーしないため、抽象化した悩みの型としてのみ扱う。今週は実装せず記録に留める。

## 2026-09-10（週次リサーチ・検索語「整体院 集客」15本）

この週も**採用ゼロ**。拾えた「ノウハウ投稿」6本が全て事実ベース原則に抵触した。
（コーパス: `docs/research/2026-09-10/knowhow_seitaiin_shukyaku.txt`）

| ノウハウの主張 | 判断 | 理由 |
|---|---|---|
| 「1ヶ月で100人集客した広告の順番」「3ヶ月先まで満席を覚悟」 | **不採用** | 検証不能な実績と希少性の煽り。factGuard・景表法の両方に抵触 |
| 「パクるの禁止」「スクショしないでください」で気を引く | **不採用** | 逆説的なエンゲージメントベイト。自社は煽らない方針、かつアルゴリズムのペナルティ対象 |
| 「スタートして1ヶ月で新規20人」の実績提示 | **不採用** | 入力に無い他社実績。捏造禁止に抵触 |
| 投稿の3点診断（①冒頭で読み飛ばされないか ②魅力が伝わるか ③予約で迷う点が無いか） | **採用済み** | 既存ルール（1行目のフック／変化を書く／導線を1つに絞る）と一致。追加実装なし。出典側の反応も8いいねで採用根拠として弱い |
| 「技術はあるけど集客が…」型の同業への呼びかけ | **不採用** | 観客が同業。見込み客に届かない |

**2週続けて同じ構図**: 「◯◯ 集客」系の検索語で伸びているのは、ノウハウ投稿ではなく
**治療院・サロンオーナー自身の弱音**（198/141/125いいね）で、ノウハウ投稿は6〜42いいね止まり。
→ 次週からノウハウ収集の検索語は「集客」系を1語までに減らし、
　 実際に見込み客が使う語（業種名＋地域、症状名など）に配分を移す。

## 2026-09-17（週次リサーチ・検索語「Threads 集客」10本）

**3週連続で採用ゼロ。** 今週のノウハウ投稿は反応が最大13コメント／いいね0〜3で、
発信者のほぼ全員が自分の商材（コンサル・広告代行・LINE特典）の入口として書いていた。
（コーパス: `docs/research/2026-09-17/knowhow_threads_shukyaku.txt`）

| ノウハウの主張 | 判断 | 理由 |
|---|---|---|
| 投稿数を増やす前に「問い合わせまでの道」（プロフィール→料金→問い合わせ先）があるか確認する | **採用済み** | 既存ルール（CVゴールを1つに絞る／導線を明記）と一致。追加実装なし |
| フォロワー数・アクセス数で満足せず、予約・来店で測る | **採用済み** | 自社READMEの「効果は表示回数でなく集客で測る」と同じ。外部から独立に同じ結論が出たことの確認に留める |
| 「開業3ヶ月で月予約140件」「SNS経由で1.4億円」の実績提示 | **不採用** | 検証不能な実績。factGuard・景表法の両方に抵触 |
| 体験後の満足・伝え方を見直す | **対象外** | 投稿生成のルールではなく来店後の接客の話 |
| ブランディング＋Meta広告に切り替える | **対象外** | 他社商材の提案。投稿生成のルールではない |
| 「保存しておこう」「必ずチェックしてくださいね」で保存を促す | **不採用** | エンゲージメントの直接要求に寄る。Metaガイドライン・自社の煽らない方針に抵触 |
| リールの装飾（キラキラ・効果音・全テロップアニメ）が派手だと「安い店」に見える。上手い店ほどシンプル | **採用済みと一致（実装なし）** | 動画の話で投稿文の直接のルールではないが、自社の装飾絵文字（✨💦）抑制ルールと同じ方向。出典の反応も2で根拠として弱い |

**ガードに関わる観察**: 集客コンサルの投稿が「『登録したからOK！』で止まっていませんか？🔍」と、
自社が禁止している同意確認の形をそのまま使っていた（反応0）。
2026-08-27以降に人間側で観測された「〜ていませんか」は
(a)「〜な人いませんか」の募集・呼びかけ (b)集客コンサルの営業投稿 のみで、
**店舗が自分の客に向けて書く文では依然ゼロ**。禁止を緩める根拠にはしない。

**今週の人間コーパス（脱毛サロン22本・居酒屋15本）は既存エントリの確認に留まった**。
両業種とも既存の `esthe` / `cafe` が match でカバーしており、
新しい win/avoid の候補（下記2件）はいずれも n=1・反応0で根拠が足りないため
**要検証として記録し、実装しない**。

| 要検証の候補 | 内容 | 保留理由 |
|---|---|---|
| 脱毛：料金表に書かれていない選定軸を挙げる型 | 予約の取り方と間隔・店舗移動の可否・解約と休会の条件 の3点を客の立場で並べる | 出典1本・反応0。かつ出典は事業者でなく美容家計の発信者 |
| 飲食：行く前の不安をつぶす具体 | 席数・カウンター何席・一人でも入れるか を駅徒歩とセットで書く | 出典1本。既存 win「場所・店名・最寄り駅からの距離を明記」の延長で、独立の勝ち筋とは言えない |

## 運用ルール

- ノウハウの採用は必ずこの表に追記してから実装する（実装先ファイルを明記）
- 「最も効果が出るもの」の判定は切り口別の実測（scheduledPosts.angle × postAnalytics）で行う。
  集計: `sh scripts/ab-post-length.sh` の切り口別セクション、または
  angle別クエリ。新しい切り口は数週間で実測順位に現れ、負ければ自動的に出現率が下がる（好み学習）
- 週次リサーチ（weekly-jp-style-research）がノウハウ投稿の収集・評価を継続する
