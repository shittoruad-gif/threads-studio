# Threads Studio 製品概要（詳細版）

最終更新 2026-09-15。数字は実測日つきで書く。取得できないものは「取得できず」と書く。
サービス内容の一次資料は `shared/productKnowledge.ts`、料金の一次資料は `shared/plans.ts`、
規模と増強の判断は `docs/scaling-thresholds.md`。この3つと食い違ったらそちらが正。

---

## 1. 一言でいうと

店舗・個人事業の方に代わって、AIがThreadsへの投稿を毎日作り、自動で公開するサービス。
毎日の操作は公式LINEのトークで完結し、アプリを開く必要がない。

**狙い**：Threadsの投稿 → プロフィール → 固定投稿 → 公式LINE → 予約、という一本道を作り、
その一本道の「毎日投稿する」部分を仕組みで肩代わりする。

**想定顧客**：整骨院・整体院・鍼灸院・ピラティス/ジム・美容サロン・飲食店など、
オーナー自身が現場に出ていて、SNSに時間を割けない小規模店舗。

---

## 2. 解決している課題

| 課題 | 従来の解 | Threads Studio の解 |
|---|---|---|
| 毎日投稿が続かない | 自分で書く／外注 | AIが毎朝6時に全件作り、予定時刻に自動公開 |
| 何を書けばいいか分からない | ノウハウを学ぶ | 登録した店舗情報＋型（地域名・1行目・締め）で自動生成 |
| 広告費がかかる | Meta広告等 | 投稿自体は無料。費用は月額のみ |
| 確認する時間がない | 溜まって放置 | LINEに本文全文が届く。見送らなければ予定時刻に公開 |
| 集客につながらない | 投稿しっぱなし | 固定投稿とプロフィールのリンクで公式LINEへ導線 |
| アカウントが止まるのが怖い | 手探り | 慣らし運転・1日の上限・冷却で出しすぎを防ぐ |

## 3. 全体像（1日の動き・すべてJST）

| 時刻 | 処理 | 内容 |
|---|---|---|
| 6:00 | 自動投稿の生成 | 全ユーザー分を並列4で生成。品質検査を通ったものだけ残る |
| 6:40 | アカウント健全性の確認 | 投稿が消えていないか。消えていれば本人と代理店へ連絡、7日冷却へ |
| 7:00 | 成績の取り込み | 表示回数・いいね等を保存 |
| 7:10 | 引き継ぎ期限の確認 | 代理店解約後30日を過ぎた配下クライアントを停止 |
| 7:20 | 決済の照合 | UnivaPayの実状態とDBを突き合わせる |
| 7:40 | 朝のまとめ | 1人1通。昨日の公開数・お知らせ・きょうやること1つ・確認待ち件数 |
| 8:00 | 承認のお願い | メール（LINE未連携の方の保険） |
| 9:05（月） | 代理店向け週次まとめ | 配下クライアントの公開数・承認待ち・止まっている先 |
| 9:30 | 社内向け報告 | LINE残枠・サーバー空きメモリ |
| 10:00 | Meta AI呼びかけ | 呼びかけ文つきカード。7日間未使用のアカウントは自動で停止 |
| 15分ごと | コメント監視 | 7:00〜21:45。新着に返信文案を付けてLINEへ |
| 30分ごと | 時刻ずらし | 7:00〜21:30。承認待ちのまま予定時刻を過ぎた投稿を先の時間帯へ |
| 18:00 | 夕方の確認 | まだ確認していない分をもう一度お知らせ |
| 予定時刻 | 公開 | 見送りが押されていなければ、そのまま公開 |

**公開時刻**（実測で反応が高い帯に合わせる。0〜29分ずらす）

- 1日1回：21時ごろ
- 1日2回：15時ごろ／21時ごろ
- 1日3回：15時ごろ／21時ごろ／22時ごろ

使い込むと、その方の反応が高い時間帯へ自動で寄る。

## 4. 主要機能

### 4-1. お店の情報の登録（オンボーディング）

公式LINEのトークで完結する。**最初は5つだけ**（ホームページのURL 1つ＋質問4つ＝業種・地域・店名・お悩み、2分ほど）。
URLを貼ると、そのページに書いてあることだけを読み取って先に埋める。書いていないことをAIが補うことはない。

続けて投稿づくりに必要な2問（お客さん像・お店の強み）を聞き、ここが埋まると投稿が動き出す。
残りは「きょうの1問」として1日1問ずつ。途中でやめても回答は残り、「続きから」で再開できる。

やり直すときは、前回の答えが「いまの登録内容」として出るので、違うところだけ直せばよい。
長い答え（25文字以上）は別メッセージで届き、長押し→コピーで一部だけ直せる。

### 4-2. 投稿の生成と品質検査

登録された事実だけを材料にする。書いていない実績・料金・数字をAIが作ることはない。
生成後、公開前に次の検査を通す。落ちた分は作り直し、それでも通らなければ見送る。

- **不自然な日本語**（naturalness）：機械的な言い回し、意味の薄い文
- **この店らしさ**（identity）：地名・店名が入っているか
- **直近との重複**（repeat）：こちらの下書きと、本人がThreadsアプリから出した投稿の両方と照合
- **健康表現**（healthClaimGuard）：効果の断定、症状名で不安をあおる書き出しなど

見送った枠は**翌朝に自動で足して届ける**（1日＋1〜2件まで）。朝のまとめに「今日の投稿に足しています」と出る。
お客様の操作は不要。

**文体のお手本**：連携時に、本人がもともとThreadsに出していた投稿（表示数の多い順に最大6件）を取り込み、
口調・絵文字・改行の癖を本人に寄せる。手で入れたお手本があれば上書きしない。

### 4-3. 公式LINEでの運用（メニュー6つ）

| メニュー | できること |
|---|---|
| 今日の投稿 | 本文全文つきカード。これで投稿する／書き直す／自分で直す／見送る |
| コメント | 新着コメントと返信文案 |
| 設定 | 1日の本数・公開前の確認あり/なし・投稿の長さ・NGワード・Meta AI呼びかけ |
| 投稿の成績 | 表示回数（平均つき）・いいね・返信・リポスト、アカウント別、上位3件 |
| 固定投稿 | 作って公開し、ピン留めまで案内 |
| お店・アカウント | 登録内容の確認、Threadsアカウント追加、ご案内先URL、スタッフ追加 |

**既定は「見送りを押さない限り、予定時刻に公開」**（2026-09-12変更）。
承認を押せない日があっても投稿は止まらない。確認そのものを不要にする「自動（確認なし）」にも1タップで切り替えられ、
設定からいつでも戻せる。

「書き直す」はAIに直させる方、「文章をコピーして自分で直す」は本文が普通のメッセージで届き、
直した全文を送り返すと差し替わる。

### 4-4. 固定投稿

プロフィールの一番上に置く「お店の入口」。400〜470字の長文で、**本文にURLは入れず**、
1件目のコメントにご案内先のリンクを付ける。締めの言い方は、登録したご案内先の種類で変わる。

ピン留めだけはThreadsアプリ側の操作（Threadsが外部からの操作に対応していないため）。
手順の案内がLINEに届く。

### 4-5. ご案内先URL

公式LINE・Web予約・ホームページ・その他（フォーム等）から選んで登録する。
投稿の誘導と、固定投稿のコメント欄のリンクに使われる。
複数登録した場合は選べる。選ばない間は、申し込みに近い順（Web予約→公式LINE→その他→ホームページ）で自動判定。

URLのドメインから種類を推定し、食い違っていれば補正する
（例：Instagram広告のLPを「Instagram」として登録すると案内文がずれるため）。

### 4-6. コメント対応

15分ごとに監視し、新着ごとに80字以内の返信文案をカードで届ける。事実だけで書き、効果の断定はしない。
返信の送信権限があるアカウントは「この文で送る」で即返信。無ければThreadsアプリが開く。

### 4-7. Meta AI呼びかけ

毎朝10時、「@meta.ai 〇〇で整体院のおすすめを教えて」のような呼びかけ文がLINEに届く。
ボタンを押すとThreadsアプリの投稿画面が文章入りで開くので「投稿」を押すだけ。
Meta AIが店名を出してコメントで答えるため、届く人が増える（実測で通常投稿の数倍〜十数倍の表示）。

APIから出すと@meta.aiがメンションにならないため、この1件だけアプリから投稿してもらう設計。
プロ・ビジネスで利用可。7日間ご本人の投稿がないアカウントは自動で送信を止め、「再開する」ボタンを1度だけ出す。

### 4-8. そのほか

- **イベント告知**：開催日を登録すると、14日前・7日前・3日前・前日・当日の5回に分けて告知を自動予約
- **個人ブランディングモード**：店舗集客ではなく個人名で発信したい方向け
- **複数アカウント・複数店舗**：アカウントごとに別の店舗情報を紐づけ、設定も個別に持てる
- **スタッフ追加**：6桁コードで別の方のLINEを足す。オーナーと同じ操作ができる
- **Keiro連携**：公式LINEに届いた合言葉（「料金」「資料」など）のヒットを投稿と突き合わせ、どの投稿から問い合わせが来たかを数える

## 5. アカウントを守る仕組み

Threadsは短時間の大量投稿・大量アクションでアカウントが止まる。実際に2026-09-12に1日8〜10件公開した日があり、
投稿が削除された。その後に入れた守りが次のもの。

- **慣らし運転**：連携直後は1日1本から。数日かけて契約本数まで増やす
- **1日の上限**：契約本数＋補填分を上限とし、本人の手動投稿も数える。超えた分は翌日へ回す
- **冷却**：投稿が消されたアカウントは7日間1日1本に抑える。消えた分は冷却明けから1日1本ずつ戻す
- **追い投稿は既定OFF**：自分で自分の投稿に返信を付ける機能は既定で無効
- **リンク付きコメントは1日1回**：その日の1件目だけ

## 6. できないこと（正直に伝える）

- **Threads以外のSNSへの自動投稿はできない**（Instagram・X・Facebook・LINE）
- **写真・動画の投稿に対応していない**（いまは文章だけ）
- **連続投稿（ツリー）はMeta社の追加審査の承認待ち**。1投稿500文字以内
- **コメント返信の送信も同じ審査の承認待ち**（文案までは作る）
- **公開後の編集・削除はできない**（Threadsアプリで削除する）
- **ピン留めはアプリ側の操作**
- **LINEに送った文章がそのまま投稿されることはない**。臨時のお知らせは「書き直す」かイベント登録で
- **APIは提供していない**（2026-09-11に料金表からも削除）

## 7. 料金（すべて税込・月額）

| プラン | 価格 | 自動投稿 | Threadsアカウント | LINEで操作できる人数 |
|---|---|---|---|---|
| フリー | 無料 | なし（手動で試用） | 1件 | 1人 |
| ライト | 4,980円 | 1日1回 | 1件 | 1人 |
| **プロ（おすすめ）** | **9,800円** | **1日3回** | **3件** | **3人** |
| ビジネス | 29,800円 | 1日3回 | 10件 | 無制限 |
| 代理店 | 55,000円 | 1日3回 | 無制限 | 無制限 |

- 決済はUnivaPay（クレジットカード）。通常申し込みは**7日間無料**、8日目から自動課金
- キャンペーン価格（モニター CPMONITOR2026／セミナー SEMINAR2026）は無料トライアル対象外。
  3回支払うと4回目から通常価格へ自動移行
- 解約はアプリのホームからいつでも。解約後はフリープランに戻り、登録内容と公開済み投稿は残る
- 推しプランは**プロ**。理由は「投稿の回数＝お客様と出会える回数」だから
  （1日1回だと外れた日は誰にも届かない／時間帯を押さえられる／数字が3倍たまる）

### 代理店プラン（55,000円）

- クライアント用ログインIDを**100件まで**発行できる。発行したIDはプロ相当（1アカウント・1日3投稿・LINE3人）
- **クライアント側に課金は発生しない**。販売価格と集金方法は代理店が自由に決める（弊社は関与しない）
- 毎週月曜9:05に代理店向け週次まとめ。クライアントの制限・投稿削除は即時連絡
- 代理店が解約しても配下クライアントは30日の引き継ぎ猶予に入り、弊社が引き継ぎを案内する
- **白ラベルではない**。アプリと公式LINEにはThreads Studioの名前が出る
  （代理店がクライアントへ出す提案資料は、当社名を出さない版を用意）

## 8. 技術構成

| 層 | 採用 |
|---|---|
| フロント | React + TypeScript + Vite + Radix UI |
| API | tRPC |
| DB | MySQL + Drizzle ORM（起動時にマイグレーション自動適用） |
| 配信 | Coolify（ConoHa VPS 4GB／4core／100GB） |
| LINE | Messaging API ＋ LIFF（公式LINE @936rschf） |
| 決済 | UnivaPay（決済リンク＋Webhook） |
| メール | Resend |
| 生成 | Gemini |
| バックアップ | Cloudflare R2（日次） |

**運用の型**：本番反映は夜間にまとめる（日中は登録中のお客様がエラーに当たるため）。
mainへのpushは5分以内に自動デプロイされるので、日中はコミットのみ。
