# 紹介ページ（/tour）とマニュアル（/manual）の自動更新について

作成：2026-08-20

## 結論

**「文章を含めて全部が自動で書き変わる」はできません。** 機能の意味は人にしか書けないためです。
そのうえで、ズレると実害が出る部分は自動化しました。現在の切り分けは次のとおりです。

## 自動で更新される

| 対象 | 仕組み |
| --- | --- |
| 実例（実際に反応が取れた投稿） | `showcase.list` が本番の `postAnalytics` を毎回参照。伸びた投稿が出れば入れ替わる |
| 実例の数字（表示・いいね・返信） | 同上。実測値をそのまま表示（加工なし） |
| 実例の匿名化 | `server/showcase.ts` が店名・駅名・地区名・番地・URL・電話・@名を伏せる |
| 掲載の可否 | `users.showcaseOptOut` を SQL 段階で参照。設定でOFFにされた時点で消える |
| 商圏カードの見た目 | `/manual` と `/tour` が `ThreadPreview` を共有。片方を直せば両方に反映 |

## 自動で検出される（テストが落ちる）

| 対象 | 仕組み |
| --- | --- |
| 説明に書いたボタン名が実在するか | `server/manualDrift.test.ts`。ボタン名を変えて説明を直し忘れると落ちる |

## 手で直す必要がある

- 機能そのものの説明文（新機能を足したとき）
- 手順の増減（画面の流れが変わったとき）

新機能を入れたら `/tour` と `/manual` も見直す、という運用は残ります。
ただし「説明にあるボタンが存在しない」という一番クレームになる形のズレは、テストで止まります。

## 実例の掲載条件

`server/showcase.ts` の定数で調整できます。

- `MIN_IMPRESSIONS = 800` … これ未満は「反応が取れた」と言えないため除外
- `MIN_REACTIONS = 3` … いいね＋返信。表示されただけの投稿を除外
- `MIN_CHARS = 62` … 冒頭を見せてなお伏せる続きが残る長さ。全文公開を防ぐ
- `EXCERPT_CHARS = 42` … 公開する冒頭の文字数
- `MAX_PER_OWNER = 2` … 1店舗で一覧が埋まるのを防ぐ
- `MAX_ITEMS = 6` … 掲載件数

2026-08-20 時点の本番データでは、3店舗から5件が該当します。
利用店舗が増えれば自動で件数と多様性が増えます。

## 見せ方の方針

冒頭1行だけを公開し、続きはサーバ側で切ってから返します（応答に全文を含めない）。
全文を出すと「これなら自分で書ける」と読まれ、数字だけが伝わって導入の理由が消えるためです。
あわせて「伸びるかどうかは文章ではなく条件（型・改行・商圏・時刻）で決まる」ことを併記し、
その条件調整を自動化する点を訴求しています。

## 同意の根拠

利用規約 第11条（実績としての掲載）。掲載範囲・匿名化措置・停止方法を明記しています。
停止は設定画面のスイッチ（`showcaseOptOut`）で、本人がいつでも行えます。
