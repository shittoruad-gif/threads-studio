社内・代理店用 — クライアントには渡さない

THREADS STUDIO 運用手順

テスター招待方式（②）の進め方

Meta審査の結果を待たずにクライアントの利用を開始するための、招待する側の手順書です。クライアント側の作業は別紙「Threads連携 かんたんガイド」を渡してください。

この方式の位置づけ
弊社アプリを開発モードのまま、クライアントのThreadsアカウントを「Threadsテスター」として登録して使ってもらう方式です。 審査通過までのつなぎとして少数のクライアントに使い、本格展開はBYOA方式（各自のMetaアプリ）または審査通過後の通常連携で行います。 審査に通れば招待は不要になり、既存の接続はそのまま正式運用に切り替わります（クライアント作業なし）。

招待の手順（1件あたり約2分）

手順 1

クライアントのThreadsユーザー名を受け取る

  • 別紙ガイドのSTEP 1で、クライアントからユーザー名（@の後ろの部分）が届きます
  • 綴りをそのままコピーして使ってください（手打ちすると間違えやすい）
手順 2

Metaダッシュボードから招待を送る

  1. developers.facebook.com にログインし、マイアプリ から Threads Studio を開きます
  2. 左メニューの アプリの役割 → 役割 を開きます
  3. メンバーを追加 を押します
  4. 役割の選択肢から Threadsテスター を選びます
  5. クライアントのユーザー名を入力し（@は不要）、招待を送ります
「テスター」と「Threadsテスター」は別物です。必ず Threadsテスター を選んでください。 間違えるとクライアント側に招待が表示されません（過去に実際に詰まったポイントです）。
手順 3

クライアントに承諾を依頼する

  • 「招待をお送りしました。ガイドのSTEP 2にお進みください」と連絡します
  • 承諾されたかどうかは、同じ アプリの役割 の画面のステータスで確認できます（承諾待ちの間は保留表示）
手順 4

接続を確認する

  • クライアントがガイドのSTEP 3（Threads Studioでの連携）まで終えたら、管理側でそのアカウントの連携状態と、翌日の自動投稿が動いたことを確認します
  • 初回投稿の確認までがこの手順の完了条件です

運用ルール（必ず守る）

ルール理由
招待を出したら必ず記録する（日付・クライアント名・ユーザー名・承諾状況）テスター枠の上限は非公開のため、何件使っているかを常に把握しておく必要があります
少数運用にとどめる。本格展開はBYOAか審査通過後にテスト用の枠を本番利用に使う方式のため、大量発行はMetaに不自然と見なされるリスクがあります
不要になった招待・退会したクライアントは役割から削除する枠の節約と、使っていないアカウントに権限を残さないため
この資料と招待画面はクライアントに見せないダッシュボードには他のクライアント名が表示されるため

うまくいかないときは

症状対処
クライアント側に招待が出ない役割の選択が「Threadsテスター」になっているか確認。「テスター」を選んでいたら削除して招待し直す。ユーザー名の綴りも再確認
クライアントがアプリ内で承諾場所を見つけられない現行UIは「設定 → その他の設定 → ウェブサイトのアクセス許可 → 招待」。それでも迷う場合はブラウザで threads.com/settings/website_permissions を開いてもらう（直URL・バージョン非依存）
承諾済みなのに連携でエラークライアントが別のThreadsアカウントで連携しようとしている可能性。連携時のログインアカウントを確認してもらう
審査に通った後はどうする？何もしなくてよい。既存接続はそのまま有効。以降の新規クライアントは招待なしで連携できるようになる
