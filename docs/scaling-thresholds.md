## 24GBにした場合、どこまで持つか（試算）
- メモリ：Threads Studio 本体は約100MB、DBは約120MB。24GB の余裕はアカウント数ではほぼ尽きない（他の15アプリとの同居分を含めても数百件規模まで）。
- 先に尽きるのは**朝の生成時間**。いまは1枠ずつ順番に作るため、40枠で75分。**連携50アカウント（150枠）で約4.7時間**になり、7:40の案内に間に合わなくなる。ここは増強ではなく並列化（コード）で解決する。
- 並列化（6並列）後の目安：24GB／8core なら **300枠（連携100アカウント前後）を約1.5時間**。**連携200アカウント（600枠）で約3時間**を超えるので、そこが「それより上」の境目。
- 「それより上」は、より大きいVPSではなく**分ける**：①生成ジョブを別サーバー（ワーカー）へ、②DBを専用サーバーへ。目安は連携200アカウント／代理店クライアント合計150件。
- 他の上限：LINEスタンダード30,000通は1人60通換算で約500人まで（超過は1通約3円で継続可）。Threads API の250件/日は1アカウントあたりなので件数には効かない。AI側の1分あたり呼び出し上限は並列化のときに確認する。

## 台帳の直し方
- 数字を更新したら日付を添える。基準を変えるときは、理由を1行で書く（例：「9/11 空き19%で警告なしに運用できているため15%を注意ラインに」）。
- 自動監視を足したら「自動監視」列に書く。監視のコードは `server/opsDigestJob.ts`（LINE枠・空きメモリ）。
