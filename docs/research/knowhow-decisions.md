# Threads運用ノウハウ投稿の採否記録

Threads上で流通する「集客ノウハウ投稿」を評価し、生成エンジンへ採用/不採用を
判断した記録。判断基準は (1)自社実測データと矛盾しないか (2)事実ベース原則
（検証不能な盛り・煽りの禁止）に反しないか (3)法規（景表法・薬機法）リスク。

## 2026-08-28（三上さん提供のスクリーンショット4系統）

### 出典1: 治療院向け8ステップ構成（感嘆→悩み名指し→権威→独自メニュー+変化→社会的証明→オファー→諦めた層回収→限定CTA）

| 要素 | 判断 | 理由・実装先 |
|---|---|---|
| 悩みで名指し | 採用済み | 既存ルール（場面まで具体化）と一致 |
| 権威づけ（資格・人数） | 条件付き採用 | 入力済みの事実のみ。→ 新切り口 reservation_funnel(2) |
| 独自メニュー+変化 | 採用 | 施術名でなく変化を書く既存ルールと一致。→ 同(3) |
| 社会的証明（遠方から来店） | 条件付き採用 | 入力に実在する場合のみ使用可（勝手に作らない） |
| オファー（元値→初回値） | 条件付き採用 | 入力済み価格のみ。→ 同(4) |
| 諦めた層の回収 | 条件付き採用 | 他店・他手法の批判にならない受け止め表現のみ |
| **限定+CTA（予約枠に限りあり・お早めに）** | **不採用** | 検証不能な希少性の煽り。factGuardの禁止事項・景表法リスク・三上さん方針（煽らない）に三重で抵触 |
| 感嘆で始める（体験者の第一声） | 採用 | customer_voice切り口と一致。実在の声のみ |

→ 実装: `shared/postAngles.ts` の `reservation_funnel`（煽り抜き版）

### 出典2: 整体院・新規103名/月の4要素（地域名・悩み具体化・今行く理由・伏字）

| 要素 | 判断 | 理由 |
|---|---|---|

### 出典3: サロン集客10箇条（1行目に客の心の声・来店後の変化・試しやすさ 等）

| 要素 | 判断 | 理由 |
|---|---|---|
| **1行目に「お客様が普段思ってること」** | **採用** | customerWords（実在の言葉）を1行目に置く指示を追加 |
| 来店後どうなるかを見せる | 採用済み | 「手に入れたい状態」ルールと一致 |
| **「たった◯分」の試しやすさ** | **採用** | 入力済みの所要時間・初回価格に限定して追加 |
| 施術で大事にしてることをセットで | 採用済み | belief/strength フィールドで実装済み |
| きれいにまとめず普段の言葉で | 採用済み | 2026-08-27リサーチで実装済み |
| 最後は質問で終わる | **不採用（会話型のみ許可を維持）** | 自社実測で問いかけ締めは文字数を揃えると負け（言い切り606表示 vs 問いかけ214表示）。会話型の投稿タイプに限定する既存方針が実測に合致 |

## 運用ルール

- ノウハウの採用は必ずこの表に追記してから実装する（実装先ファイルを明記）
- 「最も効果が出るもの」の判定は切り口別の実測（scheduledPosts.angle × postAnalytics）で行う。
  集計: `sh scripts/ab-post-length.sh` の切り口別セクション、または
  angle別クエリ。新しい切り口は数週間で実測順位に現れ、負ければ自動的に出現率が下がる（好み学習）
- 週次リサーチ（weekly-jp-style-research）がノウハウ投稿の収集・評価を継続する
